# E2E/UI-тестирование Aviasales

Практический проект автоматизированного тестирования сайта [Aviasales](https://www.aviasales.ru/) на **Playwright + TypeScript**.

В проекте реализовано **24 E2E/UI-теста** для поиска авиабилетов, дат, пассажиров, маршрутов, классов обслуживания, фильтров и покупки билета.

Основная часть работы была посвящена не только написанию тестов, но и **стабилизации E2E на динамическом веб-приложении**: исследованию DOM, асинхронного рендеринга и причин flaky-поведения.

### Что особенно интересно

В процессе разработки были найдены и устранены реальные причины нестабильности тестов:

- `page.goto()` завершался раньше, чем появлялись результаты поиска;
- `locator.count()` возвращал текущее состояние DOM, а не ожидал появления элементов;
- после применения фильтра старые карточки некоторое время оставались в DOM;
- структура карточек билетов менялась между загрузками;

Для синхронизации используются **Playwright auto-waiting, assertions и `expect.poll()`**, а ожидание привязывается к фактическому состоянию интерфейса, а не к фиксированным `sleep`.

Например, при нестабильном раскрытии фильтра тест повторяет действие до наступления ожидаемого результата:

```ts
await expect.poll(
    async () => {
        await agentsFilter.click();
        return setFilter.isVisible();
    },
    { timeout: 10_000 }
).toBe(true);
```

### Устойчивые локаторы

В ходе исследования DOM обнаружены разные варианты корневого элемента карточки:

```text
ticket-preview
bdui-ticket-preview-normal-...
```

Поэтому используется fallback-стратегия: сначала проверяется точный `ticket-preview`, затем более специфичный `ticket-preview-normal`.

Таким образом локаторы описывают именно тот объект DOM, который нужен тесту.

### Сквозной E2E-сценарий покупки

Один из тестов проверяет полный пользовательский путь:

```text
Москва - Санкт-Петербург, дата
        ↓
фильтр «Авиасейлс»
        ↓
выбор билета
        ↓
предложение «Напрямую у Авиасейлс»
        ↓
переход на booking
        ↓
проверка URL и query-параметров
        ↓
проверка данных перелёта
```

Тест не ограничивается проверкой наличия кнопки: данные выбранного билета извлекаются из карточки и затем сравниваются с данными на booking-странице.

Проверяются, в частности:

- аэропорты отправления и прибытия;
- дата;
- `adults`, `children`, `infants`;
- города отправления и прибытия;
- наличие формы пассажира.

Это позволяет проверить передачу данных через несколько этапов пользовательского сценария.

### Набор тестов

```text
tests/
├── 01/
│   ├── dates.spec.ts
│   ├── homepage.spec.ts
│   ├── route.spec.ts
│   └── travel-class.spec.ts
├── 02/
│   ├── filters.spec.ts
│   ├── passengers.spec.ts
│   ├── purchase.spec.ts
│   └── search-results.spec.ts
└── helpers/
    └── helpers.ts
```

Покрыты:

- поиск и маршруты;
- фиксированные и плавающие даты;
- пассажиры и ограничения;
- классы обслуживания;
- фильтры;
- результаты поиска;
- переход на booking;
- покупка билета.

Для работы с датами создан общий helper `getSearchDate()`, поэтому тесты не зависят от конкретного календарного дня запуска.

### Инструменты

**Playwright · TypeScript · Node.js · Allure · Git · GitHub Actions**

Тесты настроены для Chromium.

Используются:

- `expect` и auto-waiting;
- `expect.poll()`;
- `trace: on-first-retry`;
- локальные timeout для тяжёлых сценариев;
- Playwright HTML Report;
- Allure Report.

### CI

Проект запускается автоматически через **GitHub Actions**.

Workflow находится в:

```text
.github/workflows/playwright.yml
```

При изменениях в репозитории тесты запускаются в CI, а результаты выполнения доступны непосредственно в GitHub Actions.

### Запуск локально

```bash
npm install
npx playwright install
npx playwright test
```

Запуск в Chromium:

```bash
npx playwright test --project=chromium
```

Открыть HTML-отчёт:

```bash
npx playwright show-report
```

---

Проект демонстрирует практический подход к E2E-автоматизации: тестирование пользовательских сценариев, работа с динамическим DOM, исследование flaky-поведения и построение устойчивых проверок вместо зависимости от фиксированных задержек.
